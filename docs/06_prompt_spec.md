# 06 提示词规格与调优记录 / Prompt Spec and Tuning Log

> P3 起持续维护。每个调用 LLM 的节点在这里登记：它问什么、要什么结构、
> 失败时怎么办、以及为什么这么写。

---

## 零、通用约束

**所有节点共同遵守：**

| 约束 | 原因 |
|---|---|
| 打分类字段必须写 `ge` / `le` 与 `description` | 不写的话不同模型会自己发明量纲——实测同一输入 qwen3.5:9b 给 95.0、qwen2.5:3b 给 3.0（[issue 002](issues/002-small-model-echoes-json-schema.md)） |
| 提示词明确「给数据，不要照抄 Schema」 | 小模型会把 JSON Schema 原样返回 |
| 单节点失败**降级不抛异常** | 日报无人值守跑，一条翻车不该让整期作废 |
| 提示词构建是**纯函数** | 单元测试断言「我们问了什么」，不花钱、不飘 |
| 相同请求命中磁盘缓存 | 调提示词时只有真正改动的那部分重新计费 |

**测试策略**：断言提示词构建与响应解析，**不断言模型说了什么**。
模型输出质量在阶段验收时人工看一次。

## 一、summarize —— 条目摘要

**位置**：`src/dna/pipeline/summarize.py`　**调用次数**：每个事件一次

### 输入

```
标题：{title}
（另有 N 家媒体报道同一事件：{其它标题}）      ← 仅多源时出现
正文：{text[:3000]}
```

正文截到 **3000 字**。3000 字足够写出准确摘要，再多只是线性增加 input token 费用；
一期几十条，差别很可观。

正文为空时改为：

```
（正文抓取失败，只有标题可用——请基于标题写，不要编造细节）
```

**这句不能省。** 不说的话模型会自信地补出一段看似合理、实则凭空捏造的内容，
而它会原样印进日报，读者无从分辨。

### 输出结构

```python
class SummaryOut(BaseModel):
    summary: str = Field(min_length=10, max_length=400, description="1~2 句中文摘要，60~120 字")
    tags: list[str] = Field(max_length=4, description="1~4 个主题标签")
```

顺手要 `tags`：日报要按主题分组，同一次调用里让模型打标签比事后再调一次便宜得多。

### 关键指令

1. 只写原文里有的，**不做推测、评价或补充背景**
2. 不要用「本文介绍了」「据报道」开头
3. 保留产品名、公司名、版本号、性能数字

### 失败处理

**降级为用标题当摘要**，`degraded=True`。标题本身就是一句话摘要，足以让读者判断
要不要点开；因为一次 API 抖动就把真实资讯从日报里删掉，代价大得多。

### 调优记录

| 日期 | 改动 | 原因 |
|---|---|---|
| 2026-09-02 | 初版 | 真机验证：DeepSeek 输出稳定，技术术语与数字保留完好 |

## 二、translate —— 双语翻译

**位置**：`src/dna/pipeline/translate.py`　**调用次数**：每 10 条一次（批量）

### 输入

```
[id: {entry_id}]
标题：{title_zh}
摘要：{summary_zh}
```

**输入是已写好的中文摘要，不是原始正文。** 译摘要比用英文重写一遍便宜得多，
而且保证中英两版说的是同一件事。

### 为什么带 id

要求模型原样返回 id，按 id 对回原条目。**只靠顺序对齐是危险的**：模型漏译一条，
后面全部错位——第 3 条的英文安到第 2 条头上，中英两版说着不同的事，
而且**不会报任何错**。

模型返回未知 id 时丢弃；漏译的条目不出现在结果里（调用方据此知道哪些没译成，
而不是拿到一个填了空串、看起来完整的字典）。

### 关键指令

1. Translate meaning, not words
2. **产品名、公司名、版本号、指标原样保留**（GPT-4o 仍是 GPT-4o；通义千问 → Qwen）
3. 标题保持 headline 风格：不加句号，不硬塞 "The"
4. 不增不减信息

### 批量大小

10 条。太大容易超出输出长度并让模型**静默漏译**——而漏译是看不出来的。

### 失败处理

返回空字典，中文版照常可用。英文版是附加产物，它失败不该让中文版也发不出去。
整段翻译（趋势综述）失败返回 `None` 而不是原文——把中文塞进英文版比缺一段更糟，
读者会以为是排版事故。

### 调优记录

| 日期 | 改动 | 原因 |
|---|---|---|
| 2026-09-02 | 初版 | 真机验证：`2TP×4USP`、`XPU Kernel`、`Layer-wise Offloading` 均原样保留 |

## 三、trend —— 当日主线提炼

**位置**：`src/dna/pipeline/trend.py`　**调用次数**：整期一次

### 输入

```
今日条目（按重要性排序）：

1. {title}
   {summary}
2. ...
```

带编号：模型可以说「其中第 2、5 条同属一个方向」，比复述标题精炼。
顺序即重要性，模型会自然更重视靠前的条目。

输入是**已压缩的摘要**，不是原始正文——综述要的是跨条目共性，喂全文只会增加成本
并让模型被细节淹没。

### 关键指令

1. 找出**跨条目的共性主线**，150~250 字
2. 可以有判断和观点，但必须建立在给出的条目上，**不引入外部信息**
3. **不要逐条复述**——那是下面的条目要做的事

第 3 条不写的话，模型会写成一段「今天有五条新闻，分别是……」的目录，
放在开头毫无价值。

### 条目数门槛

少于 **4 条不调用 LLM**。两三条新闻谈不上「趋势」，硬写只会得到一段把标题
重述一遍的废话，而且还要花钱。

### 失败处理

返回 `(None, [])`。日报没有综述照样成立——它是加分项不是必需品。

### 调优记录

| 日期 | 改动 | 原因 |
|---|---|---|
| 2026-09-02 | 初版 | 真机验证：5 条输入下正确提炼出「效率与成本优化」这条共性主线，未逐条复述 |

## 四、不用 LLM 的节点（刻意的）

| 节点 | 为什么不用 LLM |
|---|---|
| `clean` | 归一化与样板剥离是确定性文本处理，用 LLM 又慢又贵还不稳定 |
| `dedup` | SimHash 与向量相似度是数值计算，LLM 判重既贵又会飘 |
| `score` | **可解释**（知道该改哪）、**稳定**（同输入同分，排序不抖）、**免费**。LLM 打分每次都飘，日报排序跟着抖，而排序本身不需要语言理解 |

LLM 更适合做「必须理解内容」的活（摘要、综述），排序和判重可以用信号量化。

## 五、费用分界

```
clean → dedup → score  │  summarize → translate → trend
──── 免费，随便跑 ────  │  ──── 每次运行都计费 ────
```

`dna digest --dry-run` 停在分界线上：先看清单，确认选题对了再花钱。

**实测成本（2026-09-02，DeepSeek）**：5 条日报 = 6 次调用 / 10.7 秒；
加英文版 = 8 次调用。第二次跑相同输入 = 0 次调用 / 0.1 秒（全部命中缓存）。
