# 13 台账工作台 / The Article Workbench

> ⚠️ 表格里的生成按钮**会调用 LLM 并产生费用**。打开界面本身不花钱。

```bash
dna gui          # 默认 http://127.0.0.1:8080
```

不想开终端就双击仓库根的 **`start.bat`**（跑一次 `create_shortcut.ps1`
可以在桌面上放一个）。见 [09_packaging.md](09_packaging.md)。

## 一、导入链接

右上角「**导入链接**」。**不调用 LLM，不产生费用**——只下载正文与媒体。

**支持一次多条，也支持直接粘一整段带链接的文字**：

```
这几篇不错：https://mp.weixin.qq.com/s/VgO-… ，
还有量子位这篇 https://www.qbitai.com/2026/09/xxx.html。
再加一个 https://zhuanlan.zhihu.com/p/2067…
```

三条都会被认出来，**结尾的中文逗号和句号会被剥掉**。不剥的话抓到的是
`https://…y7g，` 这种带标点的地址，直接 404——而真实的投递就是从群聊里复制出来的
一段话，链接夹在中文之间。同一个链接粘两次只算一条。

输入框下面实时列出「识别到 N 条链接」并逐条显示。粘一整段聊天记录时，
**这是唯一能提前发现少粘了一条、或者多认了一个图片地址的机会**——
抓完再发现，台账里已经留下垃圾行了，而每一行都要单独花钱生成文案。

三个开关：下载配图 / 下载视频 / 已抓过也重抓（默认关，避免重复下载）。

抓完的结果会把账报清：`识别 3 条，成功 2，降级 1（正文没抓到，可用 dna sync 手动补）`。
只报「入了 N 条」的话，少掉的那几条去哪了没人知道。

命令行等价：`dna add <链接…>`，两边调的是同一个 `intake_urls`。

## 一bis、从订阅导入

右上角「**从订阅导入**」，挨着「导入链接」——这两个是同一件事的两种来源。
**同样不调用 LLM，不产生费用。**

| 控件 | 默认 | 说明 |
|---|---|---|
| 订阅源 | 全选 | 选项来自 `config/sources.yaml` 里**当前启用**的源，包括一次还没抓过的新源 |
| 最近几天 | 3 | 只要这个天数内发布的条目 |
| 每源上限 | 10 | 每个源最多入几条 |
| 下载配图 / 下载视频 | 开 / 开 | |
| 已抓过也重抓 | 关 | |

「最近几天」是**这一次的意图**，不写回 `sources.yaml`——那里的按源配置是长期偏好。

> **没有发布时间的条目不受天数限制，会照常导入。**很多 feed 不给 pubDate，
> 按「未知即旧」丢掉的话整个源都抓不到（和评分里「缺 `published_at` 打 0.5 分」
> 是同一个理由）。

一个源失败不影响其余源，结果里会点名：
`新增 12 篇（跳过重复 3）　·　1 个源失败（infoq）　·　媒体未下载 2（不影响正文）`。
不点名的话，一个 feed 挂掉只会让人觉得「今天新闻有点少」。

抓取过程中左下角的提示条会一直走数：
`从 7 个源采集最近 3 天（不调用 LLM）　5/17　·　OpenAI 发布 GPT-…`——
这一批共几篇、做到第几篇、当前在抓哪一篇。一批十几篇要跑几分钟，
一句不变的「采集中…」分不出「在跑」和「卡住了」。「导入链接」同样有。

命令行等价：`dna fetch --days 3 -n 10`，两边调的是同一个 `intake_sources`，
转圈行上也是同一份进度（`采集 5/17 · OpenAI 发布 GPT-…`）。

## 二、这张表是什么

一篇文章一行，每种产物一列：

| ☐ | 标题 / 来源 | 正文 | 媒体 | 总结 | 短视频 | 口播 | 长文案 |
|---|---|---|---|---|---|---|---|
| ☑ | DeepSeek-V4-Flash… | 4069 字 | 10图 | ● 265字 `EN` | ● 31s | ● 2min | ● 7min |

标题下面还有一行小字：**原文链接本身**（过长会截断，悬停看完整地址），
点它在新标签页打开原文。显示链接而不是「原文」两个字，是因为
「这是不是我想找的那篇」经常光看域名就能判断。

英文版**不单独占一列**：它和中文版是同一份东西的两个语言版本，
切换在展开面板里，格子上只挂一个 `EN` 标记表示「这一格已经有英文版了」。

**点任意一格 → 下面展开这一格的内容**，重做、下载、打开素材文件夹都在展开面板里。

单元格状态：

| 显示 | 含义 |
|---|---|
| `● 31s` / `● 258字` | 已生成。**显示时长而不是「已完成」**——时长才是这个产物合不合格的判据 |
| `●`（橙色） | 生成了，但**字数没落进目标区间**。悬停看「⚠️ 未落入 X~Y 字，可手动删减或重做」 |
| `○ 未生成` | 还没做过 |
| `▲ 失败` | 试过但失败了，悬停看原因 |
| `— 不适用` | 本篇撑不起（例如正文不足 800 字，做不了长文案） |

**每种状态都同时有形状和颜色**，不是只靠颜色。色觉障碍者、以及发出去的黑白截图
里都要能分辨——只用绿/灰/红的话这两种情况下整张表就没有信息了。

超长的格子**仍然是实心 `●`**：它确实生成了，只是没达标，和「失败」是两回事。

> **超长与否是画表格的时候现算的，不存进库。**所以在设置里把字数窗口一改，
> 历史产物会跟着重新判定；存一个布尔值进去的话，改完窗口整张表还是旧结论。

### 正文格与媒体格能点开

- **正文格** → 用系统默认程序打开 `article.md`
- **媒体格** → 打开 `images/`，没有图就打开 `videos/`

**没东西可开的格子保持原样、不可点**——不给出一个点开是空的按钮。
（在**运行工作台的那台机器上**打开；服务端不在本机时会拒绝并说明原因。）

### 勾选与批量操作

每行最前面一个复选框，表头那个是「全选本页」。**勾选跨刷新保留**，
所以先筛选、再翻页勾几篇、最后一起处理是可行的。

勾中任意一篇，图例那一行就变成批量条：

```
已选 3 篇　[重新抓取]　[删除]　[清空选择]
```

- **重新抓取**：确认框里带「下载配图 / 下载视频」两个开关，然后**逐篇**重抓，
  提示条实时显示 `2/3`。半分钟的等待只给一个不动的转圈，和卡死看起来一样。
  某一篇失败**不中断**其余，跑完汇总「成功 X · 降级 Y · 失败 Z」。
  不调 LLM，不产生费用。
- **删除**：见下一节。

> 点复选框、点标题下的原文链接都**不会**连带展开这一行。

### 删除

确认框里先把要删的东西数清楚：

```
将删除 3 篇 · 5 份产物 · 3 个目录（21 个文件）
· DeepSeek-V4-Flash 正式版开源…
· …
☑ 同时删除磁盘文件
outputs\articles\20260902\DeepSeek-V4-Flash-正式版开源__decef4a4
不可撤销：重抓也拿不回已经下线的图和视频。
```

- 数字是**删之前真去算的**（`plan_delete()`），确认框上写的就是接下来真要删的那批
- 列出前 10 篇标题与前 3 个目录路径，多的折成「另有 N 篇 / N 个目录」
- 关掉「同时删除磁盘文件」就只删台账行与产物记录，目录留着
- 目录删除前会校验它确实在 `outputs/articles/` 之下——`store_dir` 是数据库里的
  一个字符串，手工改坏过的值不该变成一次 `rmtree`。不在范围内的**台账行照删、
  目录留给人手工处理**，并在确认框里点名是哪一篇
- **先删文件再删数据库行**：中途失败时台账未动，重跑能接着删；反过来的话行没了，
  那个目录就再也找不到了

命令行等价：`dna delete <id…>`（`--keep-files` 保留文件，`--yes` 跳过确认）。

### `NEW` 标识：刚导入、还没动过

标题前面挂一个**青蓝色的 `NEW`**（带轻微呼吸效果），整行左侧也有一条青蓝竖线——
只靠标题旁边一个小标签，横向滚动到右边就看不见了。

判定条件**两个同时成立**：

1. **是人工投递进来的**——界面上粘的链接，或飞书投的；RSS 抓来的不算
2. **一条产物记录都没有**——包括失败的那种

**标识一直挂着，直到对这篇调过一次 LLM 为止**，不会因为过了一夜就消失。
生成任意一项产物后标识立刻消失（表格生成完会自动刷新）。

失败的尝试**同样清掉标识**：失败记录说明 LLM 已经调过了、钱已经花了，这篇不再是
「没动过」；而且那一格本身显示 `▲`，和 `NEW` 摆在一起是自相矛盾的信号——
一个说「还没开始」，一个说「试过而且出错了」。

**为什么按来源而不按时间**：这里原先有一个 24 小时的时间窗，因为实测台账 37 篇里
有 32 篇从来没生成过任何产物（RSS 存量大多如此），只看「有没有产物」的话
`NEW` 会挂在 32 行上。窗口确实压住了泛滥，**但它压错了维度**——
它让「昨天粘进来、今天还没处理」的链接第二天失去标识，而那恰恰是最需要标识的一条。

真正要区分的是**来源**：人工粘的是「我特意要处理的」，RSS 抓的是候选池。
按来源过滤后实测只有 5 行挂 `NEW`，既解决了泛滥，也不会因为过了一夜就把待办清空。
见 [issue 010](issues/010-redo-cache-and-new-badge.md)。

配套两处：筛选栏的「**只看新导入**」开关，以及右上角的「`N` 条新导入」计数。
`NEW` 用的是**第四种颜色**（青蓝），和已生成（青绿）、会计费（琥珀）、
失败（红）都分得开——复用颜色会让人把「新导入」误读成「已完成」。

### 重做按钮为什么不在格子上

格子只有 108px 宽，按钮和「打开内容」的点击区域挨在一起，而这两件事的代价
**完全不对等**：一个免费，一个是一次计费调用。

现在重做在展开面板里，等于要求「**先看见内容，再决定要不要重做**」——
这本来就是重做之前该走的一步。按钮还是琥珀色，和其它操作在视觉上分开。

## 三、四种产物 × 两种语言

| 产物 | 时长（默认，以 profile.yaml 为准） | 文件 | 进 `--all` |
|---|---|---|---|
| 总结 | — | `summary.zh.md` | ✅ |
| 短视频文案 | **25~35s** | `shortvideo.zh.md` | ✅ |
| 口播文案 | **1~2min** | `narration.zh.md` | ✅ |
| 长文案 | **5~15min** | `longform.zh.md` + `.json` | ❌ **按需** |

四种产物**都可以出英文版**，文件名换成 `.en.md`（音频换成 `.en.wav`）。
英文版不进 `--all`，见下一节。

### 展开面板里能做什么

点开一格之后，右上角一排按钮：

| 按钮 | 作用 |
|---|---|
| 📄 | 下载文案（`.md`） |
| `{}` | 下载 `longform.zh.json`——按发言人切好的轮次，供 TTS 分配音色（仅长文案） |
| ⌇ | 下载音频（`.wav`）—— 还没合成时禁用 |
| 🎬 | 下载成片 —— **P6 视频合成后可用**，现在是禁用状态 |
| 📁 | 打开产物目录 |
| 🖼 / 🎞 | **直接打开 `images/` 或 `videos/`** —— 要拷的是素材本身，少点一层 |
| ⌇ 合成音频 | 本地 TTS，**不花钱，但花时间**。tooltip 里写着预估等待 |
| ⚙ TTS 操作台 | 校对文本、逐段挑音色、逐段生成。**点它不会开始合成** |
| 中文 / English | 切语言版本。**切换本身不花钱**，只是换一份来看 |
| 修改指令 | 开关 + 输入框，给这次生成加一句额外要求 |
| ⟳ 重做 | 琥珀色，标着预估调用次数。**这是唯一会花钱的按钮** |

素材按钮**只在目录真实存在且非空时才出现**——点开是个空文件夹比没按钮更让人困惑。

成片按钮现在摆出来但点不动：不摆的话没人知道将来会有，摆了却能点则是骗人。

### 合成音频

三种口播类产物（短视频 / 口播 / 长文案）都能一键合成，音频落在同一个产物目录里。

- **按钮不是琥珀色。**琥珀色在这个界面里专表示「这会计费」；音频跑在本地、
  一分钱不花，用同一个颜色会让「花钱」这个信号贬值。
- **稿子还没生成时按钮禁用**——先有稿子才有音频，这个顺序不该由一次失败来教会人。
- 实测 RTF≈2.5：短视频约 75 秒，口播约 6 分钟，**长文案约 37 分钟**。
  预计超过 5 分钟的会先弹确认框。
- 合成期间提示条显示 `12/47 段（已产出 83 秒音频）`——
  半小时的等待只给一个转圈，人分不清是在跑还是卡死了。
- **重新合成不会把稿子重新调一遍 LLM。**下游重做免费，上游重做花钱，
  一个动作不该同时触发两者。

### TTS 操作台

「合成音频」旁边、隔一条竖线的那个按钮，开一个对话框。这是**每天都用的那块面板**，
不是罕用功能：调文本、校对生成内容都在这里做。

```
┌ 口播稿 · TTS 操作台 ───────────────────────────────────────────────────────┐
│ ● 在线 127.0.0.1:8300                                                      │
│ ☑ 统一声音配置  (内置音色|音色设计|克隆参考音频) [音色▾] [语气指令      ]   │
│                 参考音频 [ref_audio/host.wav▾] ☐只用音色向量 [上传]        │
│                 用服务端已有的音色；「语气指令」只调语气。                 │
├────────────────────────────────────────────────────────────────────────────┤
│ 整篇文案  [每段字数上限 120] [按此文案拆分] [从分段回填]                   │
│ ┌────────────────────────────────────────────────────────────────────────┐ │
│ │ 大家好，今天这条…（整篇可编辑，拆分的输入）                            │ │
│ └────────────────────────────────────────────────────────────────────────┘ │
├────────────────────────────────────────────────────────────────────────────┤
│ 分段  [重新拆条] [加一段] [清空]                        [全部生成]        │
│ 1 ✔ ┌───────────────────────────────┐  38 字  ▶ 🎲 ✕                       │
│     │ 大家好，今天这条…（可编辑）   │  [pause][laugh][sigh][breath]        │
│     └───────────────────────────────┘  ▸ 单独配置                          │
│ 2 ✎ ┌───────────────────────────────┐ 132 字  ▶ 🎲 ✕                       │
├────────────────────────────────────────────────────────────────────────────┤
│ 共 5 段 · 3 段已生成（本次只需合成 2 段，复用 3 段）· 生成本段不写台账      │
│                                        [全部合成并保存到这篇文章]          │
└────────────────────────────────────────────────────────────────────────────┘
```

- **点开不合成。** 从前这里是一个紧贴「合成音频」的 `ui.switch`，瞄着开关点常常
  命中按钮，于是走了默认合成路径。现在是一个描边按钮，中间隔一条竖线。
- **正文可编辑，改完会写回稿子。** 点「全部合成并保存」时先把面板里的文本写回稿子
  文件，并在台账里插一行 `calls=0` 的「人工校对」，然后才写音频那一行。这样
  「这一版到底念了什么」仍然只有一个答案。**长文案例外**——它的稿子按发言人分轮
  存在 JSON 边车里，一段纯文本写不回去，面板会在顶部说明这一点。
- **`✔ / ✎ / ○` 三态**：已生成 / 生成后改过（缓存作废）/ 没生成过。
  改文本或换声音配置都会让这一段的缓存作废——否则会拿旧波形去拼新文本。
- **`▶` 生成本段免费、不写台账，而且它的音频会被复用。** 逐段校对好之后
  「全部合成并保存」只重跑改过和没生成过的段（底栏那句「本次只需合成 N 段」）。
  RTF≈2.5，不复用等于逐段校对白做。
- **`🎲` 换种子重掷**：文本和音色都对、只是这一版念得不好听时用它。**第一次生成
  不带种子**，所以第一版和自动合成出来的是同一版。
- `[pause]` 等按钮往这一段**末尾**插事件标记（服务端 `events: true` 已解析）；
  要插在中间就直接在文本框里手打。`[pause:400ms]` 与引擎无关，一定生效。
- `重新拆条` 把所有段拼起来按自动合成的切法重切，**文本没变的段保留已生成的音频**；
  它不会再跑一次朗读友好化（那是 LLM 调用，而面板里的文本已经预处理过了）。
- **服务状态一直看得见。** `ensure_service()` 会自动拉起服务并等最多两分钟；
  界面上看不出这一步存在时，「点了没反应」和「模型正在冷启动」是同一个观感。
  服务离线时面板照样能开，音色框退成自由文本。
- **「全部合成并保存」和自动合成是同一条落盘路径**（`produce(segments=...)`）：
  production 行、真实时长、字幕一样不少。

- **先有整篇，再有分段。** 顶部那个框装的是整篇文案（打开时就是稿子的正文），
  改完点「按此文案拆分」切成分段；`每段字数上限` 默认 120（与自动合成一致），
  **调小就切得细**——`split_for_speech` 是按句子往上凑到上限，所以 120 会把几句
  短句凑成一段。「从分段回填」把下面各段拼回这个框（在分段里改完、想整篇再读一遍时用）。
- **「全部生成」逐段跑完 `○` 和 `✎`，`✔` 的跳过。** 全部变 `✔` 之后，底栏那个按钮
  自己改名成「拼接并保存到这篇文章（无需重新合成）」——后端一段都不会重发，
  只做拼接、算真实时长、出字幕。
- **字幕按这次的分段出**，一段一条，时间轴取每段波形的真实长度（不是服务端报的
  秒数——那个误差会累积）。文件是音频同名的 `.srt`，展开面板里新增了下载按钮。
- **三种模式都在这里**：内置音色 / **音色设计** / 克隆参考音频。切模式时无关的控件
  会**灰掉而不是隐藏**（隐藏会让人以为「没这个功能」），下面那行小字说明这个模式
  看哪个输入框——音色设计的必填项就藏在「语气指令」那个框里。缺必填项时点生成会
  当场提示，而不是等几十秒收一个服务端 422。
- **这是唯一的 TTS 界面。** 从前右上角有个「打开完整 TTS 界面」，会拉起 TTS 模块
  自带的另一个 NiceGUI 进程；那个进程一关窗就整体退出，而且它写盘的位置不受台账管。
  整套交接单的路（`/gui/handoff` 轮询、产物回收）已删除，音色设计搬到了这里。

完整说明见 [14_tts_guide.md](14_tts_guide.md)。

### 中文 / English

四种产物都能出英文版，开关在展开面板里。**默认中文**，切过去才生成英文——
英文版单独计费，而且不进 `--all`：多数文章不需要它，跟着批量跑等于每篇都翻倍。

| | 英文版怎么来 | 一次多少调用 |
|---|---|---|
| 总结 | **翻译**已写好的中文版 | +1（缺中文版时会先补一次） |
| 短视频 / 口播 / 长文案 | **原生重写** | 与中文版相同 |

**文稿类为什么不翻译。**中文 30 秒的稿子翻成英文不是 30 秒的稿子——
英文更占篇幅，一段忠实的译文总会更长。而时长正是这三种文案的验收标准，
刚按人工参考稿校准过一轮（[issue 008](issues/008-copy-information-density.md)）。
走翻译等于把那一轮作废，还让英文稿的实际时长无声地不可控。

**英文总结更短。**提示词要求至多 45 词，schema 上限也从 800 收到 400 字符。
英文说同一件事本来就更占字符，而总结是在固定宽度的列里显示的——
溢出的部分才是人真正会注意到的。压缩只许砍虚词与连接词，
原文里的每一个数字、模型名、benchmark 都必须留着。

收起状态下语言开关是看不见的，所以**已经有英文版的格子上会挂一个小小的 `EN`**——
那正是「还要不要再花一次钱」的判断依据。

### 修改指令

重做之前想改要求，就打开这个开关写一句：

```
加长到 40 秒
多引用原文的具体数字
用词再专业一点，不要用「大幅提升」这类说法
多讲局限和代价
```

它会**接在提示词末尾**，优先级高于默认要求——放在最后是因为后出现的指令权重更高，
而这段的用途正是覆盖前面的默认要求。

指令会记进台账，下次展开这一格时**自动预填上次写过的那句**。
调稿子是渐进的：上次写了「用词再专业一点」，这次多半是在此基础上再加一条，
而不是从零重想。

> 写了指令的版本，面板左上角会用琥珀色显示「指令：…」——
> 内容读起来不对时，第一个该看的就是它。

> 「打开文件夹」是在**运行工作台的那台机器上**开窗口。默认绑 `127.0.0.1`，
> 服务端和浏览器本来就是同一台机器；如果你把它绑到 `0.0.0.0` 给别人访问，
> 这个按钮会拒绝执行并说明原因，而不是在服务器上悄悄弹一个窗。
>
> **Windows 有时仍会拒绝把窗口激活到最前**，此时资源管理器只在任务栏闪一下。
> 前台权归当前活跃的浏览器所有，程序这边已经做了让权和顶窗口（`ShowWindow` +
> `SetForegroundWindow`），但系统保留否决权。窗口是开着的，点任务栏即可。

短视频稿与口播稿都带**主标题 + 副标题**（发布时标题栏要填，写在产物里就不用
再想一遍，也保证标题与文案出自同一次生成、口径一致）：

```markdown
**主标题：** DeepSeek-V4-Flash 开源
**副标题：** 304B 极限量化，本地部署成本骤降

**口播（约 31 秒 · 289 字）：**
DeepSeek-V4-Flash-0731 正式版开源，保留相同架构与参数规模，仅重做后训练…
```

时长区间与字数窗口都取自 `config/profile.yaml`，不是写死在代码里
（`video/narration/longform_duration_seconds` 三项 +
`summary/shortvideo/narration_chars` 三项）。**改配置即改验收，以那个文件为准。**

全部存在**文章自己的目录**里：

```
outputs/articles/20260902/DeepSeek-V4-Flash-正式版开源__decef4a4/
├── article.md          正文
├── meta.json  references.md
├── images/  videos/
├── summary.zh.md       ← 以下由工作台生成
├── summary.en.md
├── shortvideo.zh.md
├── narration.zh.md
├── longform.zh.md
└── longform.zh.json    ← 按发言人切好的轮次，供 TTS 分配音色
```

## 四、长文案：专题 / 访谈

**默认不生成**，需要单独点。点下去会先弹一个确认框，让你选形式并看清预估成本：

| 形式 | 角色 | 适合 |
|---|---|---|
| **专题** | 单角色讲述 | 单人播客、深度解读 |
| **访谈** | 主持人 + 嘉宾 | 双人对谈，需要两个音色 |

**为什么单独拎出来**：它一篇要 5~9 次 LLM 调用（提纲 1 次 + 每节 1 次），
是其余三项加起来的两倍多。跟着批量跑的话，一次误操作就是十几倍的账单。

**时长跟文章体量走，不硬凑 15 分钟。** 正文短于 800 字的直接拒绝（格子显示 `— 不适用`），
不发请求。这是刻意的：不够料的文章硬做出来一定是注水稿，而注水恰恰是
「白话」的来源——模型会用背景铺垫和重复论述填满剩下的时间。

生成方式是**先出提纲再逐节展开**，不是一次写完。3000~4000 字远超单次输出的
可靠范围，硬要一次生成，模型会在中途丢失结构、重复论述、越写越水。

### 给 TTS 的 JSON

```json
{"mode": "interview",
 "speakers": {"host": "主持人", "guest": "嘉宾"},
 "est_seconds": 443.0,
 "turns": [{"speaker": "host", "text": "开源模型本地部署，现在最大的门槛是什么？"},
           {"speaker": "guest", "text": "门槛主要在参数量。GLM-5.2 和 Kimi-K3…"}]}
```

专题模式产出**同样的结构**（`mode: "feature"`，全部 `speaker: "narrator"`），
所以 P6/P7 的 TTS 照着 `speaker` 分配音色即可，不必分两条代码路径。

## 五、文案的写作要求

### 第一要求是信息密度

时长是固定的，而且发布时视频还会**加速播放**，所以稿子的成败在于**同样的秒数里
装进多少事实**。「不要白话」不是用词问题——一句没有数字、没有专有名词的话，
就是白占了那两秒。

四种产物共用一套约束：

> 1. **信息密度优先**。每一句都必须携带至少一个具体信息点——一个数字、
>    一个专有名词、一项能力、或一个明确结论。写不出信息点的句子直接删掉
> 2. 使用准确的技术术语，不要用「非常厉害」「大幅提升」替代具体指标
> 3. 模型名、版本号、benchmark 名称、数值**必须与原文完全一致**
> 4. 不确定的技术细节宁可不写
> 5. **禁止**：填充语、单独占一句的过渡句（「这意味着什么」）、
>    第一人称主观表达（「我最关注的是」）、用形容词堆出来的结尾

第 5 条逐条点名而不是笼统地说「不要白话」——**笼统的禁令模型无法执行**。
这几类都是从真机产出里挑出来的实际问题。

### 各自的取向

- **短视频**：**覆盖文章主干**。第一句必须是事件本身（谁开源了什么，带完整版本号），
  之后每句换一个新事实。主标题写事件，副标题堆亮点
- **口播**：必须有技术深度，说清方法、数字和数字为什么成立。只把结论念一遍是
  不合格的——那是短视频稿的活。结尾落在具体建议或具体数字上，不用形容词收束
- **长文案**：展开方法与取舍、给出数据、**必须有一节讲局限**。只讲好处的长稿
  没有可信度。访谈模式下主持人只提问不讲技术内容，且明确禁止互相吹捧

> **短视频这条约束改过一次。** 初版要求「一条只讲一个点」，产出技术上正确却
> 没把文章讲清楚：观众听完知道某个量化档位的困惑度没变，却不知道这是哪个模型、
> 发布了没有。现在要求覆盖主干。

### 结尾引导语

视频稿结尾固定用 `config/profile.yaml` 的 `cta_line`：

```yaml
cta_line: "关注我，下期分享 AI 行业最新进展"
```

放配置而不是写死在提示词里——这是**账号品牌**，换栏目就要换；
而提示词是「怎么写好文案」的规则，两者变更频率完全不同。

### 输入

文案的输入是**正文**而不是摘要——摘要已经把技术细节压掉了，拿它写口播只能
得到更白的白话。

正文上限 **6000 字**（摘要节点是 3000）。摘要每条都跑，一期几十条，上限乘以
条目数；文案单篇按需跑，宽一点只影响这一次调用。3000 字不够：实测一篇 4069 字
的技术稿，被切掉的尾部含采样参数和一条关键局限，而那正是「必须说局限」要用的料。

## 六、时长怎么保证

时长是硬约束：超了在平台上会被截断。所以生成之后由程序量一遍，超出区间就
带着「你写长了 N 字」回炉重写，**最多 2 次**。

反馈给的是具体字数而不是「请缩短」——模糊的指令换来模糊的修改，
模型要么砍掉一半要么几乎没动，两种都要再花一次调用。

三次仍不达标时**返回结果而不是报错**，完成提示里标
「⚠️ 超出目标字数区间（342 字，目标 200~300）」——报确切数字，人才知道是手删两句
还是重做。一篇 38 秒的稿子仍然可用。

这个提醒**留得住**：表格里那一格是橙色的实心 `●`，刷新之后还在，
悬停能看到「未落入 X~Y 字」。只在完成提示里闪一下的话，刷新一次就再也找不着了。

### 「写多少字」和「量多少秒」不是同一个换算

配置里写的是秒数，提示词里给的是字数，两者之间的换算**必须按中英混排的实际密度**：

| | 25~35 秒对应的字数 |
|---|---|
| 按纯中文 4.5 字/秒 | 112~157 字 |
| 按混排实测密度（×1.5） | **168~235 字** |
| 人工撰写的参考稿 | 199 字 / 27.8 秒 |

这曾经是「文案信息量不够」的机械原因，而且**完全静默**：按 4.5 折算，模型照
112~157 字写完，时长恰好落在区间下沿——验收通过、回炉不触发，只是信息量少掉
三分之一，没有任何环节报错。

所以 `profile.yaml` 里的字数窗口是按混排密度标的。**具体数值以
`config/profile.yaml` 为准**——本文档不复述它，抄一份出来只会各自漂移。

回炉的差值也按**上一稿实测的密度**算，不用固定系数——纯中文稿约 4.5 字符/秒，
堆满量化档位名的技术稿接近 9，用常数换算高密度稿只会被少要求删一半，
第二稿仍然超时，白花一次调用。

> **长文案仍有偏差**：分节生成的稿子实测时长仍可能低于目标（`UD-Q8_K_XL` 这类
> 标识符各节分布不均）。改用混排密度后目标字数已提高 50%，但精确校准留到
> 长文案精细化打磨。

## 六bis、重做为什么一定会给出不一样的稿子

`--force` 与界面上的「重做」都**不走 LLM 响应缓存**。

缓存故意不设过期，键是「provider + 模型 + 完整提示词」——同样的输入永远给同样的
输出，这正是它平时的价值（反复调提示词时，只有真正改动过的那部分要重新付费）。
但「重做」的字面意思就是要一份不一样的：照常走缓存的话，模型确实被调了、
文件确实被重写了，内容却一字未变，看起来就像**「生成了但没保存」**。

这是 2026-09-06 实测报上来的问题，见
[issue 010](issues/010-redo-cache-and-new-badge.md)。

想更有把握地拿到不同结果，就配上「修改指令」——它同时改变了提示词，
既错开缓存，又真正引导了方向。

## 八、命令行对等

界面上能做的，命令行都能做（两边调的是同一个 `dna.produce.service`）：

```bash
dna add <链接…>                                          # 导入链接（不产生费用）
dna produce <id> --all                                  # 常规四项
dna produce <id> --kind narration                       # 单项
dna produce <id> --kind narration --force               # 重做（重新计费）
dna produce <id> --kind longform --variant interview    # 长文案须显式指定
dna produce <id> --kind summary --lang en               # 英文版
dna produce <id> --kind narration --force -i "加长到 2 分钟"   # 带修改指令重做

dna tts                                                 # 检查 TTS 后端（秒回，不合成）
dna produce <id> --kind narration_audio                 # 合成口播音频（本地，不花钱）
dna produce <id> --kind longform_audio                  # 长文案音频（约 37 分钟）
```

三种 `*_audio` 同样**不在 `--all` 里**。理由和长文案不同：
长文案拦的是账单，音频拦的是「点一下之后这台机器半小时没法用」。

## 九、配图数量与水印

每篇默认存 10 张图、2 个视频。改法：

```yaml
# config/profile.yaml —— 全局
max_images_per_article: 10
max_videos_per_article: 2
```

```yaml
# config/sources.yaml —— 按源覆盖
  - id: arxiv-cs-ai
    max_images: 0        # arXiv 摘要页本来就没有配图
  - id: qbitai
    max_images: 20       # 长文配图多
```

**水印不做处理。** 实测量子位、微信的图片水印是发布方在上传时烧进像素的，
抓取时绕不开——探测过 `i.qbitai.com` 的各种变体，只存在带水印的那一个版本。
去除发布方水印后再发布，也与本项目一贯强调的可追溯署名相抵触。

## 九bis、设置面板（右上角齿轮）

四个标签页，写回两个文件。**改完点保存**，不逐项即时生效——一个字数窗口是一对数，
改到一半上下限是反的，即时保存会在那一瞬间把配置写坏。

| 子页 | 写回 | 管什么 |
|---|---|---|
| 内容偏好 | `config/profile.yaml` | 抓什么、存多少、出哪种语言 |
| 文案 | `config/profile.yaml` | 三个字数窗口 + 三个时长窗口 + 结尾引导语 |
| TTS | `.env` | 服务、音色、参考音频、产物 |
| 运行设置 | `.env` | LLM、密钥、网络、运行 |

「哪个 key 用哪种控件、归哪一页」收敛在 `settings_dialog.FIELD_SPECS` 一张表里，
渲染和保存都走这张表。分成四页之后最危险的失败是**某一页的控件建了但保存时没人收**
——静默丢配置，界面上还显示保存成功；这张表是那个失败的解法，
`tests/frontends/test_workbench.py` 里有一条测试盯着它与 `Profile` 模型逐字对齐。

### 内容偏好 → `config/profile.yaml`

关注 / 排除 / 视频关键词 · 日报条目上限 · 摘要句数 · 每篇存图与存视频上限 · 输出语言。

- **三个关键词框都能直接打字**，回车即新增，点 chip 上的 × 删除。
  （之前只配了 `new-value-mode` 而漏了 Quasar 的 `use-input`，于是那个框根本没有
  可打字的输入区——「支持新增」的配置形同虚设。一个能打字但看不出能打字的控件
  等于不能打字，所以框下面留了一行提示。）

- **只有改过的项会写回去。**全量写回会把 `git diff config/profile.yaml` 塞满
  没变的行，而这个文件是靠读 diff 审的。
- **注释一个字节都不动。**`profile.yaml` 里那些「为什么」是这个项目最贵的资产之一,
  所以写回是按行改值，不是 `yaml.safe_dump` 重写整个文件。
- 区间写反（`[100, 80]`）会被**当场拒绝**并给出原因。它能通过类型检查，然后让
  「落在区间内」永远为假——每一篇产物都被标成超长，而配置文件看上去毫无问题。

### 文案 → `config/profile.yaml`

三个字数窗口（验收标准）· 三个时长窗口（仅进提示词与记账）· 视频稿结尾引导语。

- **每个朗读类字数框后面实时显示估算音频时长**，改数字的同一刻秒数就跟着动。
  换算用的是 `dna.narration.duration.seconds_for_units()`——和验收时量时长用的
  是同一个函数，界面另写一份必然和它漂开。条目摘要不朗读，所以那一行不估时长。
- **估出来的秒数落在同名时长窗口之外时那一行会标黄**并写明两个区间。
  这是这个子页真正的价值：两组数字此前各配各的，谁也不知道它们对不对得上。
  **只提示，不阻止保存**——时长窗口不参与验收。
- 改完字数窗口，**表格里的超长标记立刻按新窗口重判**（它本来就是现算的）。

### TTS → `.env`

| 分组 | 字段 |
|---|---|
| 服务 | 服务地址 · 模块目录 · 解释器 · 自动拉起 · 启动超时 · 请求超时 |
| 音色 | 合成模式 · 主播音色 · 嘉宾音色 |
| 参考音频 | 主播参考音频 / 参考文本 · 嘉宾参考音频 / 参考文本 |
| 产物 | 合成前预处理 · 输出字幕 · 产物子目录名 |

三处比「一个输入框」更该做的：

- **音色下拉从服务实时取**（`available_speakers()`，带缓存）。服务离线时退成
  自由文本框并标红说明——手打一个不存在的音色名，错误要等几分钟的合成跑完才出现。
- **参考音频给候选下拉 + 就地试听**，路径解析不到时标红。候选来自
  `data_dir/ref_audio/`，存回 `.env` 的是**相对路径**——绝对路径会把配置绑死在这台机器。
  解析规则直接复用 `dna/tts/factory.py::_ref_audio_path`，界面不另写一套：
  路径写错时后端只打一条 warning 就退回内置音色，界面上看着是绿的、合成出来不是那个人。
- **换合成模式会把无关字段灰掉**：`custom_voice` 下参考音频不生效，`voice_clone`
  下音色名不生效——服务端把「同时给参考音频和音色名」当成互相冲突的参数**直接报错**。
  灰掉的字段不提交，`.env` 里的旧值原样留着（换回来还在）。

### 运行设置 → `.env`（白名单）

| 分组 | 字段 |
|---|---|
| LLM | 主用提供方 · DeepSeek 模型 · 接口地址 · 备用提供方 · OpenRouter 模型 · 启用响应缓存 |
| 密钥 | DeepSeek API Key · OpenRouter API Key |
| 网络 | HTTP 代理 · HTTPS 代理 · 不走代理的地址 |
| 运行 | 默认语言 · 每源最多取几条 · 日志级别 |

四条护栏：

- **密钥只显示前 7 位与长度，留空表示不修改。**界面会被截图。
- **被系统环境变量遮盖的字段标红并禁用**，旁边写明「改 .env 不生效」。
  `Settings` 的优先级就是环境变量压 `.env`；不标出来的话人会改十遍都没反应。
  禁用的项也不会被提交——`.env` 里不该多出一个与实际行为矛盾的值。
- **DeepSeek 模型那一栏写清楚哪个是推理模型**（慢 30~50 倍，界面会像卡死）。
  上一轮排查「GUI 卡住」的根因就是这一行被改成了推理模型，而界面上完全看不出来。
- **保存后点名哪些改动要重启**（代理与日志级别）。路径类设置（`DATA_DIR` /
  `DB_PATH`）**不在白名单里**：改了要重启，而且改错就是台账失联。

命令行等价：`dna config`（只读，密钥同样打码）。
