# 011 · 修改指令关不掉、字数与秒数对不上（2026-09-06 实测第二轮）

实测报了四条，台账里有完整证据：

```
14:45:41  shortvideo  chars=440  33.6s  calls=2  instructions=None
14:46:38  shortvideo  chars=428  33.0s  calls=2  instructions=长度增加到40s，可以多一些原文引用
14:47:33  shortvideo  chars=432  31.2s  calls=3  instructions=长度增加到40s，…
14:48:31  shortvideo  chars=454  36.6s  calls=3  instructions=长度增加到40s，…   ← 报警那次
```

## 1 · 「修改指令」关掉后仍然生效（已修）

输入框的文字与开关状态原本合成一个 `state["instructions"]`，
`bind_visibility_from` 只把输入框**藏起来**，值还在，重做时照旧发出去。
而这个值是从上一版台账里**预填**的——所以一旦用过一次指令，
之后每一次重做都还带着它，且界面上看不出任何痕迹。

改成两个字段：`use` 是开关，`instructions` 是文字。
关掉的意思是「这次不要这句要求」，不是「把它删了」——文字要留着，再打开时还在。
判断本身提成 `detail_panel.effective_instructions()`，因为它是**花钱路径上的判断**。

## 2 · 「多次生成报错」＝ 指令与时长窗口在打架（不改代码）

`长度增加到40s` 对上短视频 25~35 秒的窗口，两边要求的东西互相排斥：
模型照指令写 40 秒 → 程序量出超时 → 回炉「删掉 N 字」→ 模型两头折中 →
三次调用打满，最后一次 36.6 秒仍在窗口外，于是弹出 ⚠️。

这不是失效，是两个都被遵守了的要求互相冲突。**不做自动识别**：
从自然语言里猜时长要求，猜错的代价是稿子长度失控，而它正是三种文案的验收标准。
要 40 秒的短视频，正解是改 `config/profile.yaml` 的 `video_duration_seconds`。

界面改了一处：警告里补上**实测秒数**，并在带了指令时注明「（本次带了修改指令）」——
超时的稿子仍然可用，人要看着具体数字决定是手删两句还是重做。

## 3 · 字数与预估秒数对不上（已修）

`chars` 记的是 `len(整个文件)`，抬头里有文章标题和整条 URL。
于是同一格里三个数字说的不是同一件事：

| | 显示 | 量的是什么 |
|---|---|---|
| 台账 / 提示 | 454 字 | 整个 .md 文件 |
| `est_seconds` | 36.6 秒 | 只有正文 |
| 文件里那行 | 约 37 秒 · 250 字 | 只有正文 |

改成只数正文（`script.chars` / `result.summary` / `result.text`）。
**历史行仍是旧数字**，重做一次即刷新——为此写一次回读全部产物文件的迁移不划算。

## 4 · 重做比首次慢：不是错觉

两个原因，都不是回归：

- **回炉次数**：6.5s/2 次 → 11.9s/3 次 → 8.9s/3 次。慢的是多出来的那次调用
- **重做不走缓存**（issue 010 的修法，本就是设计）：首次生成可能命中缓存秒回，
  重做一定是真调用
